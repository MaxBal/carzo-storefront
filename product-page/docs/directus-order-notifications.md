# Сповіщення про нові замовлення

Налаштування зберігаються у singleton-колекції
`carzo_notification_settings`. Її бачать адміністратори та користувачі з
комерційною роллю Carzo.

## Канал

Поле `channel` підтримує чотири режими:

- `off` — не надсилати сповіщення;
- `email` — Directus Inbox та email користувачам із `directus_user_ids`;
- `telegram` — повідомлення чатам із `telegram_chat_ids`;
- `both` — обидва канали паралельно.

Помилка будь-якого каналу записується у серверний лог, але не скасовує вже
створене замовлення. Старий Flow `Carzo — Нове замовлення` вимкнений, щоб не
створювати дублікати.

## Email

`directus_user_ids` містить UUID користувачів Directus. Для кожного створюється
вхідне сповіщення з посиланням на замовлення. Directus також надсилає email,
якщо у профілі користувача ввімкнено `Email Notifications`, а на сервері
Directus налаштований SMTP або інший поштовий транспорт.

## Telegram

Окремий singleton `carzo_telegram_bot_settings` містить:

- `chat_ids` — ID приватних чатів, груп або каналів;
- `bot_token` — секретний токен від BotFather.

Бот має бути доданий до групи/каналу та мати право надсилати повідомлення.

Токен у Directus відображається замаскованим. Уся колекція доступна лише
адміністратору та технічному server-side API застосунку. Значення
`TELEGRAM_BOT_TOKEN` у `.env.local` та Vercel лишається резервним: воно
використовується, якщо поле Directus порожнє. Старе поле `telegram_chat_ids` у
налаштуваннях сповіщень приховане та використовується лише як резерв під час
переходу.

## Шаблон

Поля `subject_template` і `message_template` підтримують:

- `{{order_number}}`
- `{{customer_name}}`
- `{{customer_phone}}`
- `{{contact_method}}`
- `{{items_quantity}}`
- `{{items_summary}}`
- `{{total}}`
- `{{delivery_method}}`
- `{{delivery_city}}`
- `{{delivery_destination}}`
- `{{delivery_point}}`
- `{{order_url}}`

Скрипт setup додає лише відсутні початкові значення і не перезаписує подальші
ручні зміни каналу, одержувачів або шаблону.
