# Управление доступом Carzo в Directus

Скрипт настройки создаёт четыре модульные политики и пять готовых ролей. Сотруднику достаточно назначить одну роль — вручную собирать разрешения по коллекциям не нужно.

## Роли для сотрудников

| Роль | Возможности |
| --- | --- |
| `Carzo Viewer` | Просмотр всего контента и коммерческих данных Carzo без редактирования. |
| `Carzo Content Editor` | Тексты, дизайны, FAQ, модальные окна, rich content и медиа. Не может менять цены, доплаты, наличие и скидки. |
| `Carzo Commercial Manager` | Цены, старые цены, наличие, доплаты, параметры доставки и уровни «Разом дешевше». Не может менять тексты и rich content. |
| `Carzo Store Manager` | Контент и коммерция вместе. Не имеет системного `Admin Access` и не управляет моделью данных, пользователями или настройками Directus. |

Записи бизнес-коллекций не удаляются навсегда этими ролями: их следует скрывать с витрины через поле `status`.

## Как выдать права человеку

1. Открыть `Settings → Access Control` или `User Directory`.
2. Создать пользователя либо открыть существующего.
3. Выбрать одну из четырёх ролей `Carzo …` из таблицы выше.
4. Сохранить пользователя.

Политики аддитивны: `Carzo Store Manager` объединяет базовый доступ, контент и коммерцию. Выдавать отдельные политики конкретному человеку обычно не нужно.

## Технический доступ витрины

`Carzo API Reader` — отдельная роль только для сервисного пользователя сайта. Она читает данные через API, не даёт входа в Directus Studio и не назначается сотрудникам.

После применения схемы:

1. Создать в Directus отдельного активного пользователя, например `storefront@carzo.local`.
2. Назначить ему роль `Carzo API Reader`.
3. Создать для него статический токен.
4. Сохранить токен как серверную переменную `DIRECTUS_READ_TOKEN` локально и в Vercel. Не использовать префикс `NEXT_PUBLIC_`.

Публичные права на коллекции Carzo удаляются. Сервер Next.js запрашивает только записи со статусом `published`, а закрытые файлы отдаёт браузеру через серверный прокси — токен не попадает в HTML или JavaScript клиента.

## Directus 12 и файлы

Конфигурация не полагается на фильтры строк, validation, presets или ограничения отдельных полей внутри разрешений: Directus 12 Core блокирует такие пользовательские правила без подходящего регистрационного ключа. Поэтому коммерческие значения физически вынесены в отдельные коллекции `carzo_brand_pricing` и `carzo_size_shipping`, а разделение ролей выполняется доступом к разным коллекциям.

Старые коммерческие поля в `carzo_brands` и `carzo_sizes`, если они уже были созданы предыдущим запуском, становятся скрытыми и только для чтения. Витрина их не использует.

Роль редактора управляет всей библиотекой файлов. Это безопасная конфигурация для выделенного инстанса Carzo. Если в этом Directus будут файлы других проектов, потребуется регистрационный ключ с custom permission rules либо отдельный файловый инстанс/хранилище.

Без регистрационного ключа Core допускает до трёх пользователей Studio. Для большего числа сотрудников или полного набора granular rules нужен подходящий ключ Directus; небольшие организации могут запросить бесплатный Open Innovation Grant.

## Применение и проверка

```powershell
Copy-Item .env.example .env.local
# Добавить краткоживущий DIRECTUS_ADMIN_TOKEN пользователя с Admin Access
pnpm directus:validate
pnpm directus:setup
```

`directus:setup` можно запускать повторно: он обновляет управляемые политики, роли и разрешения до описанного состояния, удаляет устаревшие права на коллекции Carzo и не затрагивает остальные системные разрешения Directus.

После настройки `DIRECTUS_ADMIN_TOKEN` следует удалить из `.env.local` или перевыпустить. Для работы витрины он не нужен.
